# ADR-0005 配置统一收敛到环境变量层

| 属性 | 内容 |
| --- | --- |
| 状态 | 已接受 |
| 决策日期 | 2026-08-11 |
| 影响范围 | Prompt 版本/模型路由/检索参数/预算/Feature Flag/限流 |

## 背景

系统需要管理连接串、鉴权、Prompt 版本、模型路由、检索参数（RRF k、TopK、rerank 开关）、预算上限、限流阈值和 Feature Flag。曾考虑引入 MySQL 动态配置表 + 热更新广播以支持不重启调参和按租户灰度，但这会引入配置一致性、传播延迟、版本回滚等额外复杂度。

当前阶段决定**优先简单可控**：把配置统一收敛到环境变量层，不做运行时动态配置与热更新。

## 决策

采用**单层配置模型：环境变量 / `.env` → Pydantic `Settings`**。

1. 所有配置项（含基础设施连接串、鉴权、Prompt 版本、模型路由、检索参数、预算、限流、Feature Flag）统一由环境变量 / `.env` 载入，经 Pydantic `Settings` 校验为强类型对象。
2. 配置在**进程启动时一次性加载并冻结**，进程生命周期内不可变；变更通过重新部署 / 滚动发布生效。
3. 每个 Run 读取的是同一份进程级 `Settings` 快照，天然保证 Run 内配置一致、可复现。
4. 不引入 `dynamic_configs` 表、不引入 `config.changed` 广播、不做内存快照热替换。

## 配置分组（同一 Settings 内的逻辑分组）

| 分组 | 示例项 | 说明 |
| --- | --- | --- |
| 基础设施 | MySQL/Redis/Milvus/Kafka 连接串、端口 | 敏感项用 Secret 引用 |
| 鉴权 | auth_mode、OIDC issuer/audience/jwks | |
| 模型 | provider、base_url、api_key、各任务 model_name | 密钥不入库、不入镜像、不入日志 |
| 检索 | RRF k、TopK、rerank 开关、召回候选数 | |
| 预算 | 最大模型调用数、Token 上限、Wall Clock、成本上限 | |
| 限流 | 单租户/单用户 QPS、并发、Token 配额 | |
| Feature Flag | 实验能力开关（如 HyDE、反思、回流） | 通过环境区分启用 |

## 后果

- 正面：组件与机制最简；无配置一致性与传播问题；Run 内配置天然一致可复现；本地开发只需改 `.env`。
- 负面：调参需重启 / 滚动发布，无法在线热调；无按租户动态灰度能力（Feature Flag 仅能按环境/部署维度切换）。
- 缓解：滚动发布配合 Canary 降低变更风险；如未来确有在线热调参与按租户灰度的强需求，再新增 ADR 引入动态配置层，且必须保持 Run 级版本冻结原则。
